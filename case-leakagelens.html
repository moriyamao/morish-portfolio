LeakageLens

A model can score well because the evaluation lets it see information it will not have in deployment. LeakageLens turns that concern into an inspectable dataset audit, with observed split evidence and a separate learned column reviewer.

A runnable auditing tool

Choose training and test CSV files, identify the binary target, and optionally declare entity IDs, timestamps and features unavailable at prediction time. The browser processes the files locally and exports JSON containing row indices and statistics rather than raw observations.

The audit detects selected-feature row matches, shared entities, timestamp interleaving and declared unavailable features. The Python CLI additionally searches a bounded sample for numeric near matches. Similar observations and shared entities require interpretation against the intended deployment; they are not automatic leakage verdicts.

The trained reviewer uses nine statistics of each feature against the training target. Model inputs contain neither column names nor raw values. Test targets do not influence column statistics or scores.

How a split inflates a score

Synthetic entity experimentMean accuracy
Random row split · five seeded runs100%
Group-disjoint split · five seeded runs50%

The same one-nearest-neighbor model is trained on repeated signatures from 80 entities and 480 rows, with a random target per entity. Random splitting rewards memorizing familiar entities. The group-disjoint split evaluates previously unseen entities, which is the deployment assumed in this example. The two splits evaluate different populations; the gap is illustrative rather than a prediction about other datasets.

The model’s limits are part of the result

Column-review benchmarkLearned F1Simple rules F1
Generated holdout · 190 columns, 10 datasets1.000.67
UCI Wine + artificial leaks · 18 columns0.500.75

The generated benchmark has 760 column cases across 40 source datasets, partitioned by source dataset. It includes legitimate strong predictors and independent controls alongside eight injected target-proxy mechanisms. The threshold is selected only on validation data.

Public-data transfer is weak: the model flags seven legitimate Wine features and misses one injection. Its precision is 0.36 and recall is 0.80. The challenge is one public source dataset with five artificial leaks, not a benchmark of naturally occurring leakage.

When the missingness mechanism is excluded from training, its holdout F1 falls to zero. High synthetic performance therefore does not establish broad leakage-detection ability. A statistical score cannot reveal feature availability or distinguish every legitimate predictor from an encoded outcome.

Reproduce and inspect

Open projects/leakagelens in the repository. The shipped-model CLI uses the Python standard library. Install its pinned requirements to rerun python -m leakagelens.train. The tests verify audits, dataset separation, numerical inference and browser/Python agreement. The README contains full commands, data attribution and limits.

References: scikit-learn leakage guidance, group-aware validation, and Aeberhard & Forina’s UCI Wine dataset (1992, CC BY 4.0). The Wine target is converted to a binary task and five original artificial proxies are injected for the challenge.
